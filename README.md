# NonGravForces 0.18.0

Non-gravitational forces, torques and partials for LEO satellites (GRACE-FO reference case; classic GRACE-A/B macro model since N-07). Third concept, designed from scratch after the audits of `SatelliteNonGravToolbox` v1 and `NonGravToolbox` v0.1.1.

* Specification and plan: `HANDOVER.md` (single source of truth)
* Theory and implementation: `doc/src/NonGravForces_Theory_and_Implementation.tex` — the source is the deliverable. CI builds the PDF on every run and uploads it as the `theoryDocument` artefact; build it locally with `pdflatex` twice in `doc/src`. No PDF is committed: the one that used to be said "version 0.1.0" for three weeks because nothing compared it with anything (HANDOVER O-38). <!-- versionScan:allow -->
* Help browser: `setupNonGravForces`, then `doc NonGravForces`

Status: 64 catalogued units, all delivered, no stubs left (`auditPackage.py` compares this number with `doc/functionlist.csv`); all are verified in MATLAB. **Version 0.18.0** (2026-10-31) models the satellite's thermal inertia: the `standard` and `precise` presets integrate Woeske's lumped wall temperatures (`thermal.model = "transient"`) instead of assuming them in equilibrium; over January 2020 the steady state's thermal recoil had led ACT1B by 8-18 s on the cross-track and radial axes, the walls take that to 2-4 s and the radial residual from 3.25 to 2.28 nm/s^2, and the radial calibration scale from 0.82 to 1.07-1.09. The native integrator path serves the walls from a temperature table (`app.DynamicsSource` 'ThermalOrbit'). Also: the SOLAARS-CF shadow model's oblateness mapping corrected (its shadow edges now within ~1 s of ACT1B's), transient walls carried correctly across `Model.series` chunks, eight defects found by a help-versus-code audit of all 64 units (among them: `provenance` hashes with exact FNV-1a, so hashes differ from the previous release's), a generated test catalogue in the theory document, and a rewritten getting-started page. The release before (2026-10-29) corrected the thermosphere density, the largest error the toolbox had: the `standard` preset now multiplies NRLMSISE-00 by an observed daily scale from ESA's Swarm POD densities, with a scale predicted from F30 and Ap (fitted to CHAMP, GRACE, GRACE-FO and Swarm densities 2000-2026) on days without Swarm (`drag.densityScale = "combined"`; a standard Model needs `'DensityScale'`). Against ACT1B over January 2020 the along-track drag scale goes from 0.44 to 0.88 (GRACE-C) and the median daily residual from 6.4 to 2.1 nm/s^2. Also new: DTM2020 as an opt-in density backend (CNES licence, academic use), the Swarm and TOLEOS density readers, and the density scale on the native integrator path. Earlier releases added multi-day calibration with one common scale (N-09), measured temperature and magnetorquer regressors (N-11a), the calibration figures (N-05), a frozen regression baseline over January 2020 for GRACE-C and -D that every release must reproduce (N-10a), and a cheaper standard preset: the gas-stream shadow is read from a table (drag changes by at most 7e-13 m/s^2), which with a bitwise-neutral restructuring halves the model's share of a calibration. **444/444 green** on Tier A after N-10b compared GRACE-D's hybrid ACH1B with ACT1B (R2026a Update 4, 2026-10-20; `tests/last_run.txt`).

Setup is the only place in the toolbox that touches the network, it does so only when something is missing, and it prints a line when it does. It fetches the IERS and CelesTrak data files the same way. GRACE-FO Level-1B comes from the GFZ ISDC archive (147 MB for one day; setup keeps only the two files it needs). With a data pool named (`DATAPOOL`, or `'DataPool'`), `'FetchPool'` also fetches the observations of the reference days into it: Kyoto final Dst, CLS F30 and TU Graz's attitude, non-conservative forces and orbits for GRACE-A/B and C/D (`'PoolDays'`); `tools/cutFixtures.py` cuts the committed excerpts from them. The toolbox is published via git only. `'FetchMsis', "never"` leaves the network alone; `NGF_NRLMSISE00` points at a copy you already have. `NonGravForces.buildMex` never fetches — it refuses and names setup. Everything except the `msis00` density backend works without any of it. See `THIRD-PARTY-NOTICES.md`. The authority is `doc/functionlist.csv`; `HANDOVER.md` Part A carries the level-by-level record.
