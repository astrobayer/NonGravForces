Error Handling

Every error passes through NonGravForces.fail(unit, mnemonic, message, ...). The identifier is always NonGravForces:<unit>:<mnemonic>; the message always ends with a correction hint after ->. Mnemonic classes:

classmeaningcaller action
input*contract violation (shape, class, range, unknown option)fix the call
dep*dependency absent, too old, or answered unexpectedlyrun the dependency's setup / update
data*data file missing, malformed, out of rangesupply or extend the data
numeric*NaN/Inf produced, singular, tolerance unreachableinspect info, tighten inputs
unsupported*a valid request the toolbox refuses by designchoose another option; no fallback exists
notImplementeda specified unit not yet deliveredsee HANDOVER.md

Principles: refuse, report or proceed — never degrade silently; no silent fallback between fidelity tiers; unknown option fields error; dependency errors propagate unwrapped; warnings are collected into info.provenance.warnings; library code never prints.
