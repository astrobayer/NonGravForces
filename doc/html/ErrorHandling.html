Error Handling

Every error passes through NonGravForces.fail(unit, mnemonic, message, ...). The identifier is always NonGravForces:<unit>:<mnemonic>; the message always ends with a correction hint after ->. The classes below are read from the help block of fail.m, which owns them.

classmeaning
input*contract violation: shape, class, range, unknown option
dep*a dependency is absent, too old, or answered unexpectedly
data*a data file is missing, malformed, or outside its range
numeric*NaN/Inf produced, matrix singular, tolerance not reachable
notImplementeda specified unit that is not yet delivered (stubs)

Principles: refuse, report or proceed — never degrade silently; no silent fallback between fidelity tiers; unknown option fields error; dependency errors propagate unwrapped; warnings are collected into info.provenance.warnings; library code never prints.
